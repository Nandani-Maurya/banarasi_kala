Banarasi Kala Auth + MSG91 OTP Flow
==================================

Current rules
-------------
1. Login never asks for OTP.
   - Customer enters email/mobile number + password.
   - Backend checks the customer table and password.

2. Create account uses MSG91 phone OTP.
   - Customer fills name, email, phone, password.
   - Frontend opens MSG91 OTP widget for the entered mobile number.
   - After MSG91 returns a verified access token, backend verifies that token.
   - Backend creates the account only after OTP verification.
   - Email is unique and phone is unique in the customer database.

3. Forgot/reset password uses MSG91 phone OTP.
   - Customer enters registered mobile number.
   - Backend checks that the mobile number exists.
   - Frontend opens MSG91 OTP widget.
   - Backend verifies the MSG91 access token.
   - Customer can then enter new password and confirm password.

Environment behavior
--------------------
Backend:
- APP_MODE=dev
  - OTP can be bypassed if MSG91 widget is not loaded, useful for local development.
  - To force real MSG91 in dev, set REQUIRE_MSG91_OTP=true.

- APP_MODE=prod
  - MSG91 OTP verification is always required.
  - Set MSG91_AUTHKEY in backend/.env.

Frontend:
- VITE_APP_MODE=dev allows local testing fallback.
- VITE_APP_MODE=prod expects the MSG91 widget to be available.

MSG91 settings from dashboard
-----------------------------
Recommended settings:
- Widget platform: Web
- Contact point: Mobile Number
- Primary channel: SMS
- OTP length: 4 digits or 6 digits as configured in MSG91
- Resend count: 2
- Resend after: 30 seconds
- OTP expiry: 15 minutes
- Token throttle: 3 hits per 300 seconds
- Temporary block: 86400 seconds

If OTP attempts are exceeded
----------------------------
User-facing message:
"OTP attempts exceeded. Please try again after 24 hours or contact support."

How to unblock your test IP
---------------------------
MSG91 owns the widget/token throttle block. It is not stored in this app database.
MSG91 does not document a public API for unblocking OTP Widget token-throttle IPs.
To unblock:
1. Open MSG91 dashboard.
2. Go to OTP > Tokens.
3. Open the token drawer.
4. Go to IPs tab.
5. Remove/unblock the blocked IP if MSG91 shows it there.
6. If the IP is not visible, wait for the configured block period, currently 86400 seconds.

Helper command:
node backend/scripts/msg91-unblock-ip-helper.js --ip 2405:201:6022:e04a:92a7:8c6e:33e0:9fee

Or save the MSG91 email body in a text file and run:
node backend/scripts/msg91-unblock-ip-helper.js --email-file ./msg91-email.txt

The helper extracts the blocked IP and prints exact dashboard steps. It cannot bypass MSG91's dashboard block because this is controlled by MSG91.

Support handling
----------------
If a customer says OTP is not working:
1. Confirm the registered mobile number.
2. Ask whether they exceeded resend/verify attempts.
3. Ask them to retry after the block period if MSG91 rate limited them.
4. If still failing, check MSG91 logs for the mobile number and contact support/admin.

Frontend UI conditions
----------------------
1. Login screen
   - Shows only email/mobile number, password, keep logged in, forgot password.
   - Never asks for OTP.
   - Invalid password or missing account shows: "Email/phone or password is incorrect."

2. Create account screen
   - Phone input shows India +91 by default.
   - Customer types only the 10 digit mobile number.
   - If customer starts with 0, frontend trims it before validation.
   - Name, email, phone, password, terms consent are required.
   - Valid phone must be 10 digits and start with 6, 7, 8, or 9.

3. OTP screen
   - MSG91 popup must not be used after exposeMethods=true.
   - Frontend uses sendOtp and verifyOtp exposed by MSG91.
   - OTP is shown as separate boxes.
   - Typing one digit moves to the next box.
   - Pasting OTP from SMS keyboard or clipboard fills the boxes.
   - Verify button is disabled while OTP is being verified.
   - Resend button is disabled while OTP is being sent.
   - UI shows how many resend attempts are left.
   - If attempts are exceeded, show:
     "OTP attempts exceeded. Please try again after 24 hours or contact support."

4. Forgot/reset password screen
   - Customer enters registered mobile number.
   - Backend first checks that this phone exists.
   - Then OTP screen opens.
   - After OTP verification, customer sets new password and confirm password.

5. Error placement
   - Errors are inline inside the auth panel.
   - When an error appears, the page scrolls to that error so the customer can see it.
