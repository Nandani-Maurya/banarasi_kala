4. How the Webhook Works
What the webhook does — step by step inside your backend
1
Validates the secret. Checks the x-api-key header against SHIPROCKET_WEBHOOK_SECRET in your .env. If it doesn't match → 401 rejected.
2
Reads AWB + order ID + status from the payload. Tries multiple field names because ShipRocket sends different formats.
3
Finds the matching order in your DB — checks shiprocket_order_id, shiprocket_return_order_id, shiprocket_exchange_order_id, and all AWB fields.
4
Detects forward vs reverse shipment — is this a delivery webhook or a return/exchange pickup webhook?
5
For RTO Delivered on a COD order: auto-cancels the order, blocks COD for that customer, sets refund_status = Not Required.
6
For RTO Delivered on a Prepaid order: calculates refund amount (paid − forward charge − RTO charge), sets refund_status = RTO Action Required.
7
Updates the order row in DB with new status, delivered_at (if Delivered), AWB codes etc.
8
Sends an email to the customer with the new status.
No Sandbox: ShipRocket does not have a test/sandbox environment. Their API always hits production. But since the webhook is just a POST to your server, you can simulate every single delivery event yourself without any courier involvement.
5. Postman Setup — Do This Once
1
Download Postman from postman.com (free). Install and open it.
2
Create a new Collection called "Banarasi Kala — ShipRocket Tests". Use this to save all your test requests.
3
Create a new Request inside the collection:
  • Method: POST
  • URL: http://localhost:5003/api/shiprocket/webhook
4
Add Headers (click the Headers tab):
KeyValue
Content-Typeapplication/json
x-api-keyPaste your SHIPROCKET_WEBHOOK_SECRET value from backend/.env here
5
Set Body → click Body tab → select raw → choose JSON from the dropdown → paste any payload from Section 6.
6
Hit Send. You should see a response like: 
{"message": "Order status synced", "orderId": 42, "status": "Delivered"}
Make sure your backend is running before sending webhook requests: cd backend && npm run dev
Finding Your ShipRocket Order ID

After placing a test order, run this SQL to get the ShipRocket IDs:

SELECT
  id,
  order_number,
  status,
  payment_method,
  shiprocket_order_id,
  shiprocket_awb,
  shiprocket_return_order_id,
  shiprocket_exchange_order_id
FROM vns_saree.orders
ORDER BY id DESC
LIMIT 10;
shiprocket_order_id may be NULL if ShipRocket push failed or the backend was offline when the order was placed. In that case use the /api/shiprocket/push-order endpoint first (see Section 3).

7. Status Mapping — ShipRocket Sends → What Your DB Stores

The mapShiprocketStatus() function in ShipRocketController.js converts ShipRocket's raw status strings to your internal status values. Any string containing the listed keywords is matched.

ShipRocket Status (keyword match)Your DB StatusType
AWB AssignedAWB AssignedForward
Picked Up / Manifest / In TransitShippedForward
Out for deliveryOut For DeliveryForward
DeliveredDeliveredForward
Undelivered / Delivery failed / Customer unavailable / Address issueUndeliveredForward
RTO InitiatedRTO InitiatedRTO
RTO In TransitRTO In TransitRTO
RTO Delivered / Return to origin deliveredRTO Delivered → triggers COD block OR prepaid refund calcRTO
CancelCancelledAdmin
Pickup Scheduled / Pickup QueuedReturn/Exchange Pickup ScheduledReverse
Picked up / Out for pickupReturn/Exchange Picked UpReverse
Returned / RTO Delivered (on reverse)Return Completed / Exchange CompletedReverse
How the system knows if it's a return/exchange webhook vs a forward delivery webhook:
It checks if the order_id in the payload matches shiprocket_return_order_id or shiprocket_exchange_order_id. If yes → reverse logic. If it matches shiprocket_order_id → forward logic.

9. Useful Database Queries for Testing
Get latest orders with all ShipRocket IDs 
SELECT id, order_number, status, payment_method, payable_amount,
       shiprocket_order_id, shiprocket_awb,
       shiprocket_return_order_id, shiprocket_return_awb,
       shiprocket_exchange_order_id, shiprocket_exchange_awb,
       is_rto, rto_count, refund_status, refund_amount,
       delivered_at, created_at
FROM vns_saree.orders
ORDER BY id DESC LIMIT 10;
Check if COD is blocked for a customer 
SELECT id, email, phone, is_cod_blocked, cod_block_reason
FROM vns_saree.customers
WHERE email = 'customer@example.com';
Manually set an order to Delivered (to test return/exchange) 
UPDATE vns_saree.orders
SET status = 'Delivered',
    delivered_at = NOW()
WHERE id = YOUR_ORDER_ID;
Manually unblock COD for a customer (to reset after testing) 
UPDATE vns_saree.customers
SET is_cod_blocked = false,
    cod_block_reason = NULL,
    blocked_at = NULL
WHERE email = 'customer@example.com';
Check order item actions (return/exchange/cancel requests) 
SELECT oia.id, oia.action_type, oia.status, oia.quantity,
       oia.item_amount, oia.estimated_refund_amount,
       oi.product_name, oia.created_at
FROM vns_saree.order_item_actions oia
JOIN vns_saree.order_items oi ON oia.order_item_id = oi.id
WHERE oia.order_id = YOUR_ORDER_ID;
Reset an order for re-testing (use carefully) 
-- Reset to fresh "Pending" state for re-testing
UPDATE vns_saree.orders
SET status = 'Pending',
    delivered_at = NULL,
    is_rto = false, rto_count = 0,
    return_requested_at = NULL,
    exchange_requested_at = NULL,
    refund_status = NULL, refund_amount = 0, refund_note = NULL,
    shiprocket_return_order_id = NULL, shiprocket_return_awb = NULL,
    shiprocket_exchange_order_id = NULL, shiprocket_exchange_awb = NULL
WHERE id = YOUR_ORDER_ID;
10. Troubleshooting
ProblemCauseFix
Webhook returns 401 Invalid webhook secret The x-api-key header value doesn't match SHIPROCKET_WEBHOOK_SECRET in .env Open backend/.env, copy the exact value of SHIPROCKET_WEBHOOK_SECRET, paste it in Postman header
Webhook returns "Order not found locally" The order_id in your JSON doesn't match any shiprocket_order_id in the DB Run the SQL from Section 9 to get the correct value. Also try using AWB: { "awb_code": "123", "current_status": "..." }
Webhook returns "Webhook ignored" The current_status string doesn't match any keyword in mapShiprocketStatus() Use one of the exact status strings from Section 7. Even small spelling differences matter — e.g. "Picked up" not "Pickup"
shiprocket_order_id is NULL in DB after placing order ShipRocket API call failed (wrong credentials, pickup location name doesn't match, or backend offline) Check backend console for [ShipRocket] ⚠️ error. Then call POST /api/shiprocket/push-order with { "orderId": X } manually
COD not blocked after RTO Delivered webhook Either the order is Prepaid (COD block only happens for COD orders) or the customer row doesn't exist Verify payment_method = 'COD' in DB. Check backend logs for [ShipRocket] webhook output
Return/exchange webhook not changing status correctly The order_id in payload is the forward shipment ID, not the return shipment ID Use shiprocket_return_order_id or shiprocket_exchange_order_id from DB, not the main shiprocket_order_id
"Return is allowed only after delivery" error Order is not in Delivered status Run SQL: UPDATE vns_saree.orders SET status='Delivered', delivered_at=NOW() WHERE id=X;
Order not being pushed to ShipRocket at all ShipRocket credentials wrong or pickup location name mismatch Check SHIPROCKET_PICKUP_LOCATION in .env — must exactly match the name in ShipRocket Dashboard → Settings → Manage Pickup Addresses
