1.2 Backend — CartService.js
MethodStock GuardBehaviour
addToCart Yes Checks product.status = 'active'. Reads color_stocks[colorId] or falls back to stock_quantity. Errors if newQty > available stock.
updateQuantity Yes Same stock check. If quantity ≤ 0, cart item is destroyed (auto-remove).

Note on removeFromCart: The CartService deletes by { customerId, productId } only — it ignores colorId. If a customer has the same product in two different colors, removing one color will remove ALL rows for that product. The frontend passes ?colorId=... as a query param, but CartRoutes must forward this to the service. Verify CartRoutes passes colorId to the service.

2. Order Cancellation Policy — Before Delivery
Window: Customers may cancel an order only within 24 hours of placing it. Requests after 24 hours are automatically rejected.
2.1 Conditions
ConditionRule
Time windowWithin 24 hours of order creation timestamp
Status guardOrder must not already be Cancelled or Delivered
After dispatchCancellation is blocked once item is Shipped / Out for Delivery / RTO statuses
MethodCustomer submits via My Orders → Cancel button
2.2 Outcome by Payment Method

COD Order Cancellation

  • Order status → Cancelled
  • refund_status → Not Required
  • payment_status → Cancelled
  • No financial refund (no money was paid)
  • Customer receives cancellation email

Prepaid Order Cancellation

  • Order status → Cancelled
  • refund_status → Refund Pending
  • Refund of full paid amount in 1–2 business days
  • ShipRocket cancellation attempted automatically
  • Customer receives cancellation + refund email
2.3 Multi-Item Orders — Partial Cancellation
  • Customer can cancel individual items within the 24-hour window.
  • If only one active item remains and it is cancelled → entire order becomes Cancelled.
  • If other items remain active → order totals are recalculated, that item is marked Cancelled, and ShipRocket is notified to update shipment.
  • Cancelled item inventory is automatically restocked.

3.2 COD Block Logic
How COD is Blocked — Backend (orderLifecycle.js)
  • Sets customer.is_cod_blocked = true on the Customers table.
  • Reason stored: "COD blocked because a previous COD order returned to seller after unsuccessful delivery."
  • Checks run at order creation: isCodBlockedForContact() matches by both email AND phone.
  • Even guest customers (no account) are blocked by email+phone combination.
  • Blocked customers who try COD at checkout get: "COD is not available for this account. Please place a prepaid order."
Customer Impact: Once COD is blocked due to RTO, the customer may only place Prepaid orders going forward. This is permanent until an admin manually unblocks.
3.3 No Refund — COD
COD orders that RTO have no financial refund obligation — the customer never paid online. No wallet credit, no bank transfer required.

4.1 Option A — Refund

Option A: Customer Chooses Refund

  • Refund is processed after deducting: Forward shipping charge + RTO shipping charge.
  • Formula: Refund = Paid Amount − Forward Shipping − RTO Charge − (any prior redispatch charges)
  • Remaining balance refunded to original payment method.
  • Customer submits bank details via My Orders → Refund Details form.
  • Admin processes and updates refund_status → Refund Paid.
4.2 Option B — Re-dispatch

Option B: Customer Chooses Re-dispatch

  • No refund is issued.
  • Customer must pay re-dispatch + delivery charges before the order is shipped again.
  • Payment link / amount shared by admin team.
  • Once payment received, admin updates: is_redispatched = true, redispatch_payment_amount recorded.
  • Order re-dispatched via ShipRocket.
  • Subsequent RTO on a re-dispatched order: refund deducts all cumulative logistics charges (original + redispatch).

5. Return & Exchange Policy — Single Product Orders
Window: Customer may request a return or exchange within 7 days of the delivery date.
5.1 Core Rules — Single Product
#Rule
1The customer must choose full return OR full exchange for the entire order — no partial allowed.
2Once a product is returned and refund is completed, no further return or exchange is accepted for that order.
3If the customer chooses exchange, the replacement product is eligible for one delivery only.
4Products received through exchange are NOT eligible for any further return or exchange.
5A customer can use return or exchange only once per order.
5.2 Exchange — Once Per Order
Backend enforces this via hasOrderExchangeHistory(order) in OrderItemActionController.js:

Checks order.exchange_requested_at OR whether any item already has an exchange action. If true, new exchange requests for any item in the same order are rejected with:
"Exchange can be requested only once for an order. Remaining products can be returned."
6. Return & Exchange Policy — Multiple Product Orders
6.1 Rules
#Rule
1Customer can choose which products to return or exchange.
2All products the customer wants to return must be included in one return request only — no split requests.
3Once a product is returned, it cannot be returned or exchanged again.
4Products NOT returned can be exchanged one time only.
5If a product is exchanged, the replacement cannot be returned or exchanged again.
6If a customer cancels an exchange request, that product loses return/exchange eligibility permanently.
7Each product: one action only (return OR exchange). After that, no further action allowed.

7. Return / Exchange Request Cancellation Window
Window: After a return or exchange request is placed, the customer may cancel it within 24 hours of submission. After 24 hours, the request cannot be cancelled.
ConditionRule
Cancellation windowWithin 24 hours of the action's created_at timestamp
Effect of cancelling an exchange requestThat product becomes permanently ineligible for return or exchange
Effect of cancelling a return requestProduct is no longer in pending state; no further return or exchange action allowed
8. Return / Exchange Shipment RTO — Customer Liability
If a return or exchange shipment is returned to us (RTO) due to:
  • Customer unavailability during pickup
  • Refusal to hand over the parcel
  • Incorrect address provided
  • Any other customer-related reason
→ The customer is responsible for the applicable RTO and re-shipping charges.
The return/exchange process will continue only after the customer pays the required charges.

10. Gaps — Missing Enforcement (Action Required)
GAP-1 — 7-Day Return/Exchange Window Not Enforced
Severity: High
File: backend/src/controllers/OrderItemActionController.js
Function: isDeliveredEnoughForPostDeliveryAction()

Currently only checks that the order is delivered — it does NOT check if 7 days have passed since delivery. A customer could request a return 30 days after delivery and it would be accepted.
Fix Required — add to orderItemActions.js
const isWithinReturnWindow = (order, windowDays = 7) => {
  const deliveredAt = order?.delivered_at ? new Date(order.delivered_at) : null;
  if (!deliveredAt) return false;
  const msSinceDelivery = Date.now() - deliveredAt.getTime();
  return msSinceDelivery <= windowDays * 24 * 60 * 60 * 1000;
};
Then in OrderItemActionController.create() and estimate(), add:
if ([ACTION_TYPES.RETURN, ACTION_TYPES.EXCHANGE].includes(actionType)) {
  if (!isDeliveredEnoughForPostDeliveryAction(order)) {
    return res.status(400).json({ message: 'Return or exchange is available after delivery.' });
  }
  if (!isWithinReturnWindow(order, 7)) {
    return res.status(400).json({ message: 'Return or exchange window of 7 days from delivery has expired.' });
  }
}
GAP-2 — No 24-Hour Cancel Window for Action Requests
Severity: High
Missing: There is no API endpoint or controller method that allows a customer to cancel a pending return/exchange request within 24 hours.
The policy states: "After a return or exchange request has been placed, the customer may cancel that request within 24 hours."
What needs to be built
  • New endpoint: DELETE /api/orders/:orderId/actions/:actionId
  • Check: action.created_at within 24 hours
  • Check: action.status is still 'Initiated' or 'Requested' (not yet approved/completed)
  • On cancellation: set action.status = 'Cancelled', revert item.status, clear pending_action_quantity
  • Special rule for exchange: if cancelled, mark item as permanently ineligible (set a flag or use a special status)
GAP-3 — Cancelled Exchange Request = Permanent Ineligibility
Severity: Medium
Currently hasUsableAction(item) only blocks items with non-rejected actions. If an exchange action is cancelled (status = 'Cancelled'), the item appears eligible again — violating the policy that "if a customer cancels an exchange request, that product will no longer be eligible for any return or exchange."
Fix Options
  • Option A: Add a boolean column exchange_action_cancelled to order_items. Set it when an exchange action is cancelled. Block any further actions on that item.
  • Option B: In hasUsableAction(), also treat 'Cancelled' exchange actions as blocking (exchange-specific).
GAP-4 — removeFromCart Ignores colorId
Severity: Medium
CartService.removeFromCart(customerId, productId) does not filter by colorId. If a customer adds the same product in two colors, removing one color removes both rows.
Fix in CartService.js
async removeFromCart(customerId, productId, colorId = null) {
  const where = { customerId, productId };
  if (colorId !== null && colorId !== undefined) where.colorId = colorId;
  return await Cart.destroy({ where });
}
Also update CartController.removeFromCart to extract colorId from req.query and pass it.
