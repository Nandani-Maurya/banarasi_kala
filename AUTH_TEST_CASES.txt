Banarasi Kala Auth Test Cases
=============================

Environment setup
-----------------
Dev relaxed OTP:
backend/.env
APP_MODE=dev
REQUIRE_MSG91_OTP=false
MSG91_AUTHKEY=your_key

frontend/.env
VITE_APP_MODE=dev

Dev with real MSG91:
backend/.env
APP_MODE=dev
REQUIRE_MSG91_OTP=true
MSG91_AUTHKEY=your_key

frontend/.env
VITE_APP_MODE=prod

Production:
backend/.env
APP_MODE=prod
REQUIRE_MSG91_OTP=true
MSG91_AUTHKEY=your_key

frontend/.env
VITE_APP_MODE=prod

Restart after env changes:
1. Stop backend and frontend terminals.
2. Start backend: npm run dev
3. Start frontend: npm run dev

Login tests
-----------
1. Valid email + password logs in.
Expected: user reaches home/account; no OTP is requested.

2. Valid phone + password logs in.
Expected: user reaches home/account; no OTP is requested.

3. Wrong password.
Expected: "Email/phone or password is incorrect."

4. Unknown email/phone.
Expected: "Email/phone or password is incorrect."

5. Empty identifier/password.
Expected: browser required-field validation or inline form validation.

Signup tests
------------
1. New valid name + unique email + unique phone + strong password.
Expected: MSG91 widget opens; after OTP verification account is created and logged in.

2. Existing email with new phone.
Expected: "Email already registered."

3. Existing phone with new email.
Expected: "Phone number already registered."

4. Invalid phone, less than 10 digits.
Expected: "Please enter a valid 10 digit mobile number."

5. Phone starts with invalid digit such as 1234567890.
Expected: "Please enter a valid 10 digit mobile number."

6. Invalid email format.
Expected: "Please enter a valid email address."

7. Password less than 6 characters.
Expected: "Password must be at least 6 characters."

8. MSG91 OTP wrong or closed.
Expected: "Phone OTP verification failed. Please try again."

9. MSG91 throttle exceeded.
Expected: "OTP attempts exceeded. Please try again after 24 hours or contact support."

10. Dev relaxed mode with MSG91 script blocked.
Expected: signup can continue for local testing only when REQUIRE_MSG91_OTP=false and VITE_APP_MODE=dev.

Forgot/reset password tests
---------------------------
1. Registered phone.
Expected: backend confirms account exists; MSG91 opens; after OTP verification reset-password form opens.

2. Unknown phone.
Expected: "No account found with this phone number."

3. Invalid phone.
Expected: "Please enter a valid 10 digit mobile number."

4. OTP verification success then new password equals confirm password.
Expected: "Password reset successfully. You can login now."

5. New password and confirm password mismatch.
Expected: "Passwords do not match."

6. New password less than 6 characters.
Expected: "Password must be at least 6 characters."

7. After reset, login with old password.
Expected: login fails.

8. After reset, login with new password.
Expected: login succeeds without OTP.

MSG91/IP block tests
--------------------
1. Trigger repeated OTP sends until MSG91 sends IP blocked email.
Expected: app shows rate-limit/support message if MSG91 returns block/throttle error.

2. Extract blocked IP from MSG91 email:
node backend/scripts/msg91-unblock-ip-helper.js --email-file ./msg91-email.txt

3. Direct helper usage:
node backend/scripts/msg91-unblock-ip-helper.js --ip 2405:201:6022:e04a:92a7:8c6e:33e0:9fee

4. Manual unblock:
MSG91 dashboard > OTP > Tokens > token > IPs tab > remove block or whitelist IP.

Regression checks
-----------------
1. Login page should not show OTP button.
2. Signup page should show "Verify Phone & Create Account".
3. Forgot password should ask for registered mobile number, not email.
4. No Firebase OTP env variables are required.
5. Auth build/lint should pass.
